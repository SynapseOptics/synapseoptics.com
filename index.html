Lens design software a script — or an AI agent — can drive

The interface an optical design program offers decides what you can automate. Ours offers three, and they are the same program underneath.

Most optical design software was built for a person at a keyboard, and the automation was added afterwards, one exported function at a time. LensHH-LT was written the other way round: the GUI, the command line and the MCP server are three front doors onto one engine, so anything you can do in the interface you can also do in a script, in your own code, or by asking an agent.

That last one is the part that is genuinely new. Through the Model Context Protocol server — tested with Claude Code and Claude Desktop — an agent can build a lens surface by surface, mark variables, author a merit function, run an optimizer, and read back MTF, spot diagrams and aberration coefficients to decide what to do next. Not a chatbot describing optics: an agent operating the tool and looking at the results.

The GUI, CLI and MCP server are open source under the MIT license, so what an agent is allowed to do is something you can read rather than take on trust. See what LensHH-LT does →

Free for students and academic research

Optical design is usually taught on software a graduate cannot afford to keep. That seemed worth fixing.

LensHH-LT is free for students and academics: the full program, not a limited teaching build, valid for two years and renewable once. Apply with your institutional email address and that is the whole process. LensHH-Pro will carry an academic discount, announced at launch.

For a course, the useful part is usually the scripting rather than the price. A problem set can ship as a file and a script; an assignment can be checked by running it.
