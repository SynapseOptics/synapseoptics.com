# SEO — what to do, and what's already handled

## The routine

1. Edit a page. Commit.
2. If the pre-commit hook blocks you, run the two commands it prints, then commit again.
3. Push.

That's the whole job. Everything below is already set up and needs no attention.

## Optional, after a real content change

Nudge Bing/Yandex/Naver/Seznam to recrawl the pages you changed:

```powershell
.\indexnow.ps1 -Urls "https://synapseoptics.com/products/lenshh-lt.html"
```

Run it after the push, once the page is live. Omit `-Urls` to submit all 14,
but only for genuinely site-wide changes — resubmitting everything for a
one-page edit is the repeated no-op traffic that gets a domain deprioritised.

Google ignores IndexNow entirely, and it affects recrawl speed, not ranking.

## One future gotcha

`docs/lenshh-lt-help.html` is generated by the LensHH-LT build. Its
`<link rel="canonical">` and `<meta name="description">` will be **lost at the
next help regeneration**. The fix belongs in that generator's `<head>` output,
not here. This is the only thing on the site that regresses silently.

## What's already in place

| Thing | Where | Maintenance |
|---|---|---|
| `robots.txt` | repo root | none |
| `sitemap.xml` | repo root | regenerated by the hook's prompt |
| Canonical tags | all 14 pages | none |
| Meta descriptions | all 14 pages | none |
| JSON-LD | `index.html`, `products/lenshh-lt.html` | none |
| IndexNow key | `<key>.txt` at repo root | none |

## Tools

- `build-sitemap.ps1` — rebuilds `sitemap.xml`; each `<lastmod>` is the last
  commit that touched that page, so the dates cannot drift.
  `-Check` verifies without writing and exits 1 if stale.
- `indexnow.ps1` — submits URLs from `sitemap.xml`. `-DryRun` shows the payload
  without sending. The key is read from the root `<key>.txt`, so rotating it
  means dropping in a new file and deleting the old one — no code change.
- `install-hooks.bat` — run once per clone to enable the hook
  (`git config core.hooksPath hooks`). Git never enables hooks automatically.
- `git commit --no-verify` — skip the sitemap check for one commit.

## Not automated on purpose

- **Ratings/reviews in JSON-LD.** Google's Software App rich result needs a
  rating or review alongside the price. There are none yet, so the Rich Results
  Test will warn about a missing `aggregateRating`. That warning is correct —
  ignore it until real reviews exist. Never invent them.
- **`softwareVersion` in JSON-LD.** A hardcoded version here would be stale
  within weeks. The help page already carries the current version if it's ever
  wanted.
- **Search Console sitemap submission.** One-time, already done. Google
  re-fetches on its own; resubmit only if the URL changes or the Sitemaps
  report shows a fetch error.
